# Client discovery packet

This directory is the client record you have at the start of the engagement:

- `discovery-sessions.json` reconstructs the material observations, corrections, requests, blockers, and unvalidated claims from the discovery history;
- `stakeholder-notes.md` records the current stakeholder positions;
- `service-baseline.json` supplies scenario measurements for the service and early retrieval pilot;
- `workflow-sample.csv` contains 48 noisy request journeys across channels, relationships, and request families. Per-row outcomes and resolution notes are withheld so the sample cannot become a shortcut answer key.
- `admission-case-snapshot.json` exposes one unlabeled requested-versus-confirmed workflow state with dependencies, owners, events, and open exceptions.

The session record is a faithful semantic reconstruction, not a transcript. Names, company identifiers, dates, vendor topology, exact figures, verbal mannerisms, and recoverable source phrasing were removed or replaced. Duplicate call artifacts and later summaries were consolidated into one observation stream. No quote in this directory should be presented as a client quote.

Treat these files as business evidence. Use them to diagnose the pain, identify contradictions, define success, choose a build priority, and prepare client questions. They are not policy sources and cannot support an employee answer. Only records in `case-data/source-documents.json` are eligible answer evidence.

The record is intentionally incomplete. Distinguish observed state from stakeholder ambition and delivery-team claim. Document the assumptions you make, the evidence that would overturn them, and what you would ask next.

The admission snapshot is not proof that a workflow completed, and it is not a validation set. The available record includes checklists and process references but no labeled end-to-end admission cases with agreed expected outcomes.
